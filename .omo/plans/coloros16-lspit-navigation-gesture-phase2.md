# coloros16-lspit-navigation-gesture-phase2 - Work Plan

## TL;DR (For humans)

**What this drives:** Phase 2 of the ColorOS 16 gesture-hook module. Device state changed — the user flashed a root host (KernelSU + Zygisk Next 1.5.0 + a framework whose module.prop reads "LSPosed v2.2.0 (7854)"). The prior plan (`.omo/plans/coloros16-lspit-navigation-gesture.md`) reached a terminal NO_GO on Task 1 because the host contract was unproven and Tasks 4-8 were all BLOCKED. This plan RE-OPENS that gate **only on fresh device-side measurement** (never on the user's spoken claim), then builds, deploys, enables, validates, and releases the real hook module that suppresses only touchscreen left/right edge-swipe Back recognition while preserving bottom Home/Recents and key Back.

**Why this approach:** The old NO_GO has a specific, now-closable evidence gap (see `task-1-reopen.json` `missing_evidence`). This device now carries a host whose versionCode (7854) is above the API-102 floor (7769), and the framework is demonstrably injecting modules into `com.android.systemui`. All remaining risk is mechanical, so the plan is strictly sequential: verify the host on-device (Task 4), replace the stale AOSP-targeting prototype with a hook against the Task-3-proven Oplus target (Task 5), deploy + headless-enable with a proven recovery path (Task 6), prove the behavior and the rollback on-device (Task 7), and only then claim SUPPORTED (Task 8). Every gate is fail-closed: a NO_GO stops dependent tasks and preserves evidence — it never silently proceeds.

**What it will NOT do:** It will not accept the user's spoken "I flashed it" as proof (Task 4 measures the device). It will not hook AOSP `EdgeBackGestureHandler.isWithinTouchRegion` (proven ABSENT). It will not veto bottom-strip events (they feed the nav-handle animation), will not touch Quickstep/OplusLauncher (pid 1457, separate process/artifact for bottom Home/Recents), will not intercept global InputDispatcher / pilfer / final `KEYCODE_BACK` / `OnBackInvoked` callbacks, will not change navigation mode, will not modify any existing plan/evidence/notepad file, and will not re-litigate the API-102 ecosystem research that `task-1-reopen.json` already closed.

**Effort / risk:** Medium implementation effort (one real hook + policy + tests + build), medium-high runtime risk because it changes OEM SystemUI behavior on a live device. Mitigated by: fail-closed hash/descriptor guards, a proven disable/recovery path exercised BEFORE first enable, a boot-crash watchdog that auto-disables, and a bounded QA window with stay-awake kept on.
